## 一、C++ 的读出(`livgo.hpp: livgoDtwLag`、`gnss_fusion_livgo.cpp: livgoTryDtw`、`collectEpoch`)

* **输入**:两条序列在同一个时间戳向量上(`dtw_tg` 与 `dtw_th` 逐元素相同,都是该 GNSS 历元的估计器时间 `t_est`)。
  * GNSS 速度 = `|dop.v_ecef|`,`dop` 是 `RobustDopplerLs::solve(ep.t_rx, in, sol.r_ecef)`(4 个未知数:速度 3 + 钟漂;位置取同一历元的 `RobustSpp` 解;只在 SPP 成功时才解);3D 范数,含垂直分量。
  * 宿主速度 = `|z|`,`z = v_g + R_g [ω_g]× l`,`ImuBridge::evaluate(core, br, lever_I, …)` 给出的天线速度(`bridge->query(min(t_est, t_k))`,桥接失败的历元整个丢掉);`l` = `gnss/frames/lever_arm_xyz`(SmartPNT (−0.118, 0, 0.12),MARS 0)。
  * 一个历元要入序列须:`dop.ok`、`z`、`v_ecef` 有限、桥接成功、`!dtw_applied`。COLLECT 是伪距驱动的:没有有效伪距的星不进任何行(`geometryAt`)。
* **时间栅格**:`t_est = t_rcv − b/c − leap(18 s) + offset + drift·(…)`;literal 臂不读 A18 文件(A81 一 2),offset = drift = 0,所以 `t_est = t_rcv − b/c − 18 s`,`b` 是该历元 SPP 的钟差(失败时用上一次的)。
  `livgoDtwLag` 把两条序列在 `[max(t0), min(t1)]` 上取**最后** `n = min(⌊(t1−t0)/dt⌋, ⌊window_s/dt⌋)` 个 `dt = grid_s` 格点(格点取中点 `t1 − n·dt + (i+½)dt`)线性插值,各自减均值、除总体标准差(标准差 ≤ 1e-6 时除 1),所以**窗口以最后一个样本为终点**。
* **Sakoe–Chiba 带**:`band_s = 2 s`(不是配置键),格数 `W = lround(band_s/dt)` = 40 / 20 / 10(网格 0.05 / 0.1 / 0.2 s)。起点格 `(0, j≤W)`,终点格取末行带内**代价最小的第一个**(严格 `<`),递推的平局顺序为对角、上、左(各严格 `<`)。
* **重叠**:重叠 `t1−t0 ≥ 3 s`、`n ≥ 20` 格、`window_s/dt ≥ 20` 格,否则返回假。
* **滞后读法与成功条件**:从终点格沿前驱回溯,每个路径格记 `(j−i)·dt`(i 是 GNSS 序列下标,j 是宿主序列下标);路径格 ≥ 10 个;取 `sorted(lags)[size/2]`(上中位数,`nth_element`)。
  符号:GNSS 比宿主晚 D,则滞后 = −D,`tmap->addOffset(lag)` 把 GNSS 的 `t_est` 提前。滞后是网格的整数倍。
  **成功只看上面这些结构条件,不看有无运动**:两条序列都恒定时标准差守卫把它们变成全零,所有格代价 0,严格 `<` 留下第一个终点格,滞后 = −band_s = −2.0 s(单测 `test_constant_series_do_not_fail_and_return_the_band_edge`,`constant` 用例已与 C++ 对齐)。
* **`dtw_min_epochs`**:`livgoTryDtw` 在 `dtw_tg.size() < dtw_min_epochs` 时直接返回,每个历元(在入序列之前)试一次,第一次成功即 `addOffset` 并置 `dtw_applied`(**一次性,整个运行不再改**)。
  它只决定第一次在序列有多长时试,窗口是 `livgoDtwLag` 取最后 `window_s`。`dtw_min_epochs = window_s / 历元间隔` 时,第一次试的序列恰有这么多样本(在 10 Hz 下跨 `window_s − 0.1 s`,所以 (0.1, 40) 实际取 398 格、(0.2, 40) 取 199 格,不是 400 / 200);默认值 30 时第一次试在约 3.1 s 的数据上,窗长 40 s 不起作用(A80 实现记录二 6)。

## 二、离线复刻与输入(第 3 项)

`dtw_scan.py` 的 `dtw_lag` 逐语句翻译 `livgoDtwLag`(同样的运算顺序、顺序累加而不是 numpy 的成对求和、同样的平局顺序、`lround` 的半数远离零),`online_first_lag` 复刻 `livgoTryDtw` 的一次性语义。

**GNSS 速度**取 `tools/fl2g/gnsslsq.py` 的 `spp` + `solve_doppler`(仓库已有的离线单历元 SPP 与多普勒最小二乘)。为什么与在线路径一致:

| 环节 | C++ | 离线 |
|---|---|---|
| 量 | `|v_ecef|` 的 DLS,位置来自同历元 SPP | 同 |
| 观测模型 | 距离率 `e·(v_s−v) + Sagnac 率(A36 的符号) + d − c·ddts`,4 个未知数 | 同一个模型、同一个 Sagnac 率符号(`gnsslsq` 文档:与 C++ 的 A36 一致,与 RTKLIB `resdop` 相反) |
| 星的选择 | 主频点;有效伪距;`cn0_hard` 的 C/N0 ≥ 35、仰角 ≥ 15°;卫星位置速度来自 bag 星历 + `nav_rinex` | 同(`obs.ls_obs` 取主频点,`psr_ok` 要求状态位 + 19000–45000 km 的 L0 距离门;C/N0 35、仰角 15°;bag 星历 + brdm/BRDC) |
| 稳健化 | LMS 子集一致 + Huber IRLS + 迭代 w 检验,权来自噪声模型 | 迭代剔除最大归一化残差(0/1,4σ),权只含仰角 |
| 时间 | `t_est = t_rcv − b/c − 18` | 同,`b` 取离线 SPP 的 GPS 钟差 |

差别在稳健化与权:离线没有 LMS 与 Huber,权只含仰角,不用接收机的 `dopp_std`(SmartPNT 的瘦身包里它是 0,RINEX 没有接收机 std)。**核对**:
* 时间轴:重建的 `t_est`(加上该 OBSERVE 运行用的 A18 映射)对 C++ OBSERVE 运行 `gnss_epochs.csv` 的 `t_est` 残差中位 0.00–10.5 µs、最大 83 µs(表 T5;SP-0707 有一个约 10 µs 的常量差,原因没有查)——比最小网格 50 ms 小三个量级。
* 速度:离线 GNSS 速度与宿主速度整段相关 MARS 0.996(rms 差 0.35 m/s)、SP-0718 0.869(含宿主失效段,见第七节)、SP-0707 0.785(接收机差)。
* 历元可用性:COLLECT 阶段 C++(OBSERVE 运行的掩码:仰角 10°、C/N0 下限 0)SPP 有效 0.907 / 0.974 / 1.000,离线(35/15 掩码)0.811 / 0.924 / 0.945;掩码不同,所以不可直接比,只说明量级(表 T5)。

**宿主速度**取 U 运行 `a80d_U3` 的 `state_trace.txt`(LiDAR 周期末状态,约 10 Hz):`z = v + R(ω×l)`,ω 由相邻周期姿态的中心差分得到,在两个周期之间对 `z` 线性插值——桥接在周期内是常加速度,速度本来就是时间的线性函数,所以与 `ImuBridge::evaluate` 的 `v_g` 同阶一致。
literal 臂在 ACTIVATE 之前不更新宿主(A80 实现记录三 2:50 m 之前臂就是 U),而 DTW 在 ACTIVATE 之前一次性触发,所以 U 的宿主轨迹就是在线一次性 DTW 看到的宿主。

两个参照点:COLLECT 开始 = OBSERVE 运行 `a80d_Tobs2`(宿主配置为 img_time_offset 0.004 的那一轮)里第一个 `COLLECT` 历元的接收机时刻(SP-0707 1720338906.4;SP-0718 1721289936.5;MARS 取 `a80d_Tobs_mars` 的 1698132988.002)。
SP-0718 的 `a80d_Tobs2` 在写本报告时还没跑完,时间轴校验用的是已写出的前 7523 个历元。

## 三、与 C++ 逐位对齐(第 4 项)

## 四、扫描与选参(第 5 项)

设计:起点 = COLLECT 开始 + 60 s·k;每个起点对 3 网格 × 4 窗长各跑一次一次性滞后(`online_first_lag`:序列从起点起每历元增长一个样本,到 `min_epochs = window/0.1` 个样本时试,第一次成功即读数)。
合并比较用**共同起点集**(最长窗 120 s 放得下的起点:SP-0707 32 个、SP-0718 34 个、MARS 4 个,共 70 个窗口/组),这样 12 组在同一批起点上比;另按"每组各自所有可行起点"重算,选中的组相同。
MAD = 未缩放的中位数绝对偏差(`fl2g.robust.mad`)。失败 = 函数在 200 次试之内都不成功或数据不够一个完整窗;共同起点集上失败 0 个。
各自所有可行起点上,失败只来自序列末尾放不下整窗:20 / 40 s 窗 0 %,60 s 窗 3.9 %,120 s 窗 7.9 %。**函数不会因运动不足而失败**(见第一节),运动不足表现为滞后是噪声(表 T1b、T2)。

## 六、旁证(第 6 项)

数据线的时间核实(`tools/datasets/README.md`、`audit/<seq>/time_calib/`)与本扫描在 literal 时间基准(`t_est = t_rcv − b/c − 18 s`,无 A18)下的独立互相关:

| 序列 | 数据线 | 本扫描:两条速度序列的互相关(1 ms 步,GNSS 晚 D ⇔ DTW 滞后 −D) |
|---|---|---|
| SP-0718 | Doppler 水平速度对真值水平速度相关 0.986,最佳滞后 0.0 s(分辨率 0.1 s);A18 xcorr 偏移 +0.0012 s(相关 0.99998,窗口散布 0.9 ms) | 60 s 窗口(相关 ≥ 0.9 的 53 / 67 个):D 中位 +0.041 s,MAD 0.028 s;整段 +0.345 s 是宿主失效段拖的(整段相关 0.867) |
| MARS | 真值时基 xcorr −0.112 s(RTK 戳在主机钟上,不确定度 0.05 s,置信"中");A18 xcorr 偏移 +0.0101 s(单窗,相关 0.993,峰宽 σ 32 ms) | 60 s 窗口(8 / 10):D 中位 −0.001 s,MAD 0.044 s;整段 +0.042 s(相关 0.996) |
| SP-0707 | Doppler 对真值速度相关只有 0.40,"不能用来定时基";A18 xcorr 偏移 −0.0100 s(窗口散布 17.6 ms) | 整段 +0.099 s(相关 0.745),60 s 窗口只有 5 / 60 个相关 ≥ 0.9,D = +0.100 s |

结论:三条序列里,GNSS 速度相对宿主的真实偏移在 ±0.05 s 以内(SP-0707 的数不可靠,在 ±0.1 s),**在 literal 时间基准下正确的 DTW 读数是 0**(0.2 s 网格下为 0;0.1 / 0.05 s 网格装不下 0.04 s 的偏移,读数在 0 与 ∓1 格之间换)。
选中组的中位是 0.000 s,与此一致;问题在尾部(41 % 的窗口 ≥ 0.2 s)。A18 文件里自带的离线 `dtw_offset_s`(+0.0900 / −0.0988 / +0.0101)是另一个量(整段 10 Hz、起止强制对齐的路径),
对前两条与 xcorr 差整一格 0.1 s,与本扫描里"路径中位数在网格间换格"同一现象。

## 七、问题与交回

1. **在线首窗是静止窗,滞后是噪声,且一次性永久生效**(影响最大)。SmartPNT 两条序列在 COLLECT 开始后分别要 167.5 s / 109.7 s 才开始运动,而 `dtw_min_epochs = 400` 使第一次 DTW 在 COLLECT 后 39.9 s 触发,
   此时宿主速度标准差 0.005–0.010 m/s,与 GNSS 速度的相关 0.04 / −0.11(T2 下方表)。选中组的首窗滞后 SP-0707 +0.4 s、SP-0718 +0.6 s(别的组 −0.8…+1.1 s),`addOffset` 把它永久加进时间映射(`dtw_applied`),
   之后 TDCP / 多普勒行按错 0.4–0.6 s 的时刻取宿主状态(SP-0718 的 0.6 s 在 16 m/s 下相当于约 10 m;SP-0707 是 0.75 m/s 的小车,0.4 s 约 0.3 m)。MARS 起飞即动,首窗 0.0。A81 的规则里没有运动门,也不能由我加;可选方案留给主循环:
   (a) 照规则做,评测时接受这个一次性噪声(与论文的一次性 DTW 同构,但 literal 臂在 SmartPNT 上会被它伤);
   (b) 加运动门(例如窗内宿主速度标准差下限)——新自由参数,须另行预登记,本扫描的 T1b 与逐窗 `host_std` 可作定值依据;
   (c) 本臂关 `livgo/dtw_online`(已有开关,A75 起):时间映射只剩数据集时基规则,旁证(第六节)说这个规则的偏移 ≤ 0.04 s(SP-0707 ≤ 0.1 s)。
2. **MAD 判据对量化盲,选中组并不好**:滞后是网格的整数倍,0.2 s 网格下过半的窗口恰好落在 0 时 MAD = 0,与另外 41 % 窗口的 \|滞后\| ≥ 0.2 s 无关(运动窗里 38 %;去掉宿主失效窗 38 %)。
   0.1 s / 0.05 s 网格的 MAD 是 0.05–0.10 s,但尾部更小(0.1 s / 120 s:13 %,0.05 s / 120 s:17 %;窗越长尾越小,120 s 窗在 SP-0707 仍有 −0.1 s 的整体偏置)。规则只看中位数离散度,看不到尾部与偏置;5 ms 的平局规则在 25 ms 量化下只合并**完全相等**的 MAD。
3. **窗长在规则下不稳定,单窗滞后不可复现**(第五节):网格 0.2 s 稳,窗长 20 / 40 在一个变体里互换。在线滞后只能当分布看。
4. **宿主 U3 在 SP-0718 的 1050–1221 s 失效**(速度与真值差 > 2 m/s;U3 该序列 e1 ATE 1212.9 m,`ate_runs.csv`),与数据线记录的"整段稳跑"不符;它污染 5 个窗口(T1c),不改变选组。若数据线有更新的 U 运行,我没有用。
5. **SP-0707 的接收机质量差**:C/N0 ≥ 35 且仰角 ≥ 15° 的卫星中位 12 颗,多普勒速度对宿主整段相关 0.785;窗口相关 ≥ 0.9 的只有 5 / 60 个;它在 (0.1, 40) 的 34 个窗口里有 18 个滞后恰为 −0.1 s(互相关给 +0.10 s,与 A18 的 −0.010 s 差一格),
   不是可靠的时间参照。
6. **输入是重建的**:GNSS 速度用离线 `gnsslsq`(无 LMS / Huber、权只含仰角),宿主速度来自周期状态;时间轴与 C++ 对到 83 µs,速度相关 0.8–1.0。第三节的逐位对齐只针对 `livgoDtwLag`;若要在线一次性滞后的**逐次**核对,需要一次 LIVGO-literal 的开发集回放(本任务没有做,A81 的顺序也在它之前)。
7. **失败不看运动**(第一节):恒定序列返回 −2.0 s;真实数据里序列有噪声所以没有触发。
8. 没有触碰评测集、`gnss/`、`config/`、AMENDMENTS、`a80-data` 与 `a80-literal`;远端只写 `/data2/fl2g/runs/dtw/`(约 16 MB:GNSS 速度 npz、全部扫描 CSV、gzip 的 dump 与 C++ 结果)与 `/data2/fl2g/_dev/a80-dtw*`(工具树与包装脚本);`/data2` 剩余 ≥ 20 GB。

## 八、复现(远端镜像内,单核;`<root>` = 第二工程根 `/data2/fl2g`)

```bash
# 1. GNSS 速度(每序列一次;--cn0-min 35 --el-min 15 是 literal 臂的掩码)
python3 tools/calib/dtw_scan.py extract-gnss --bag <root>/smartpnt/bags/<seq>.bag --nav <brdm> --out gnss_<tag>.npz
# 2. 时间轴校验(对 OBSERVE 运行 + 该运行用的 A18 文件)
python3 tools/calib/dtw_scan.py validate --gnss gnss_<tag>.npz --obs-epochs <obs run>/gnss_epochs.csv --calib <A18 yaml> --out validate_<tag>.json
# 3. 扫描(--dump 给 C++ 对齐;--collect-t-rx = OBSERVE 运行第一个 COLLECT 历元的接收机时刻;--lever = gnss.frames.lever_arm_xyz)
python3 tools/calib/dtw_scan.py scan --seq <seq> --gnss gnss_<tag>.npz --host-run <U run> --lever -0.118 0 0.12 --collect-t-rx <t> --out scan_<tag>.csv --dump dump_<tag>.txt
# 4. C++ 对齐:编译 tools/calib/dtw_align.cpp(第三节的选项),再比较
dtw_align dump_<tag>.txt > cpp_<tag>.txt && python3 tools/calib/dtw_scan.py compare --dump dump_<tag>.txt --cpp cpp_<tag>.txt
python3 tools/calib/dtw_scan.py synth --dump synth_dump.txt        # 合成边界用例,同样的 compare
# 5. 选参与表格
python3 tools/calib/dtw_scan.py select scan_*.csv                   # A81 规则;--all-starts:每组各自所有起点
python3 tools/calib/dtw_scan.py xcorr|motion|hostcheck ...          # 第六、七节的旁证与诊断
python3 tools/calib/dtw_scan.py report --dir <结果目录>             # 本报告的全部表格
python3 -m unittest discover -s tools/calib/tests                   # 单测
```
